# ADR-0007：界面关闭后的「后台核心模式」

- 状态：已接受（2026-09-11，用户提出）；**v1 部分落地**（见文末修订注）
- 关联：ADR-0001（sidecar 架构）、ADR-0006（内存预算）

## 背景

架构里最贵的是 Flutter 界面进程（实测 63–100 MB），Go 后端只要 20–40 MB（`推测:`）。用户要求：关闭界面时**可以选择只留后端核心常驻**，省下界面那份内存，同时保住已建立的连接、热缓存和 MCP 服务。

## 决策

1. **设置项「界面关闭后保留核心」**，默认开启（本 ADR 的目的就是省资源；不改默认的用户在设置里关）。
2. 关闭界面 = Flutter 进程退出，Go 后端继续运行；**完全退出 = 托盘菜单里「退出」**。
3. **托盘图标归后端所有**（Go 侧 `fyne.io/systray` 或 `getlantern/systray`，三平台支持），菜单：打开界面 / 退出核心。不能放界面进程里——界面退出后托盘就没了，等于没省。
4. 界面重启 = 新 Flutter 进程按 `~/.lazydb/runtime`（端口 + 令牌）发现并附着到已在跑的后端；发现不了才拉新后端。附着失败重试一次后降级为拉新。

### 资源账

| 状态 | 进程 | 内存 |
|---|---|---|
| 界面开着 | UI + 后端 (+ 活动驱动) | 83–140 MB `推测:` |
| **后台核心模式** | **后端 only** | **20–40 MB `推测:`** |

## 后果

- 后端成为长寿进程：连接池、缓存索引常驻，界面秒开（附着比冷启动快，利好 ADR-0006 的 ≤1s）。
- `lazydb mcp-server` 仍是独立子命令（ADR-0005），不依赖本模式；本模式的增益是连接与缓存的热度。
- macOS 上后端需要 Accessory（不占 Dock）形态，Windows/Linux 常规托盘——实现期验证。
- 「退出核心」必须连带回收全部驱动代理进程（ADR-0002 的生命周期规则），不重演 GoNavi 僵尸进程。

## 修订注（2026-09-12，v1-10）

v1 落地形态：附着/重启/退出回收驱动全链路已实现（`~/.lazydb/runtime` 附着、`POST /api/shutdown` 触发后端 `srv.Close` → `driverhost.Close` 回收全部驱动进程）。**托盘未实现**：三平台托盘库（getlantern/systray 等）在 darwin/linux 均需 cgo，与「Go 侧 CGO_ENABLED=0 交叉编译」（spec #15 实施决策）冲突。v1 以界面内「退出后端」按钮替代；托盘升级决策（引入 cgo 或平台原生方案）留待需要时再开 ADR。
